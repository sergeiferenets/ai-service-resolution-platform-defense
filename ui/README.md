# Демонстрационный интерфейс

Streamlit поверх API платформы. Нужен для показа сквозного сценария на защите и для записи короткого видео.

Интерфейс ничего не вычисляет: он отправляет обращение в API и показывает ответ. Правило, гипотеза, гарантия, исполнение, срочность и согласование приходят с платформы. Своего состояния, кроме идентификатора текущего обращения, он не хранит; собственной базы, фоновых задач и аутентификации у него нет — пользователь выбирается из списка и передаётся в заголовке `X-User-Id`, как и в остальных обращениях к API.

## Запуск на узле

Поднимается рядом с платформой отдельным профилем:

```bash
docker compose --profile core --profile app --profile ui up -d --build ui
```

Порт открыт только на петле узла (`127.0.0.1:${UI_PORT}`, по умолчанию 8501), поэтому с рабочей машины он открывается через туннель:

```bash
ssh -N -L 8501:127.0.0.1:8501 root@<узел>
```

Дальше — `http://localhost:8501` в браузере.

## Запуск на своей машине

Нужен доступ к API — обычно тем же туннелем к порту 8000 узла:

```bash
pip install -r ui/requirements.txt
API_URL=http://127.0.0.1:8000 streamlit run ui/app.py
```

## Порядок показа, 60–90 секунд

1. **Обращение.** Выбрать пример «Ошибка 50.2 на МФУ HP», при желании приложить фотографию таблички из `data/eval/nameplates`. Отправить.
2. **Разбор.** Показать состояние, определённое оборудование и уровень достоверности, гипотезу со ссылками на фрагменты документации, правило, предварительную гарантию, способ исполнения, срочность и необходимость согласования.
3. **Решение человека.** Нажать «Подтвердить» и показать номер черновика в учётной системе.
4. **Границы.** Развернуть «Технические подробности»: три агента без заглушек, шаги обращения с вызовами инструментов, версия набора артефактов.
5. **Права.** Переключиться на «U-019 — представитель партнёра» и открыть то же обращение: обоснование на внутреннем материале не показывается, трассировка закрыта.

Пример «Правило, требующее оценки» показывает разделение ответственности на R-06: Rule Engine выбирает candidate по модели и коду, а Policy Agent проверяет по описанию симптома связь с конкретным заданием и отсутствие автономного воспроизведения без USB/LAN. В блоке решения появляется вердикт применимости со ссылками на переданные факты; route остаётся значением из каталога правил.
