# Инфраструктура MVP

Развёртывание выполняется одним скриптом. Ручных шагов нет: сервер прерываемый и может быть
пересоздан в любой момент, поэтому любое действие, не зафиксированное в коде, считается утраченным.

```bash
git clone <репозиторий> && cd service-desk-ai-platform
sudo bash infra/bootstrap.sh
```

Скрипт идемпотентен: повторный запуск на настроенной машине ничего не пересоздаёт и не меняет
сгенерированные пароли.

| Команда | Что делает |
|---|---|
| `sudo bash infra/bootstrap.sh` | Полный проход: пакеты, драйвер, Docker, toolkit, стек, проверка |
| `sudo bash infra/bootstrap.sh --boot` | Только поднять стек. Используется юнитом systemd после перезагрузки |
| `sudo bash infra/bootstrap.sh --check` | Диагностика без изменений |

## Целевая машина

Selectel, облачный сервер: NVIDIA GeForce RTX 4090; runtime сообщает 49 140 МиБ видеопамяти, 12 vCPU, 64 ГБ RAM, Ubuntu 22.04, диск 200 ГБ.
Развёрнуто и проверено на текущем MVP GPU node; драйвер 580.178.04.

Требование к ускорителю жёсткое: квантование AWQ по ADR-0005 требует архитектуры Ampere или новее.
RTX 4090 относится к архитектуре Ada Lovelace (sm_89), условие выполняется. На более старых картах нужных
вычислительных ядер нет и стек не запустится.

## Профили

Стек разделён на три профиля, чтобы отказ наблюдаемости не блокировал работу платформы.

| Профиль | Сервисы | Роль |
|---|---|---|
| `core` | `vllm-llm`, `vllm-vision`, `vllm-embeddings`, `postgres`, `qdrant` | Без них система не работает |
| `app` | `api`, `mock-erp` | Включается автоматически, как только в `backend/` и `mock-erp/` появятся Dockerfile |
| `observability` | Langfuse v3 (+ собственный PostgreSQL, ClickHouse, Redis, MinIO), Prometheus, Grafana | Инструменты разработчика |

`bootstrap.sh` поднимает `core`, дожидается готовности, затем запускает `observability` в фоне.
Недоступность наблюдаемости не задерживает готовность стека и не роняет развёртывание.

**Langfuse — инструмент разработчика, а не система аудита.** Аудиторский след платформы ведётся
в PostgreSQL профиля `core` по схеме `docs/architecture/data-model.md` (сущность `AUDIT_EVENT`).
Ни один сервис профилей `core` и `app` не ссылается на Langfuse: приложение обязано работать при
его недоступности.

```bash
docker compose -f infra/docker-compose.yml --profile core ps
docker compose -f infra/docker-compose.yml --profile observability logs -f langfuse-web
```

## Модели

| Роль | Репозиторий | Лицензия | Доля видеопамяти |
|---|---|---|---|
| Языковая | `Qwen/Qwen3-8B-AWQ` | Apache-2.0 | 0.40 (≈19 ГБ) |
| Обработка изображений | `Qwen/Qwen2.5-VL-7B-Instruct-AWQ` | Apache-2.0 | 0.27 (≈13 ГБ) |
| Векторные представления | `BAAI/bge-m3` | MIT | 0.08 (≈4 ГБ) |

Обоснование выбора — ADR-0005 и `docs/architecture/model-card.md`.

Веса лежат на хосте в `MODELS_DIR` (по умолчанию `/opt/models`) и монтируются в контейнеры.
В образах весов нет: на прерываемой машине повторное скачивание 15 ГБ при каждом пересоздании
контейнера недопустимо.

Экземпляры vLLM стартуют строго последовательно. `--gpu-memory-utilization` — это доля **полного**
объёма видеопамяти, и каждый экземпляр измеряет свободную память при запуске. При одновременном
старте замер оказывается неверным и карта переподписывается.

### Обязательно при обращении к языковой модели

У Qwen3 режим размышления включён по умолчанию и возвращает блок `<think>…</think>`. При трёх
последовательных агентах это ломает целевое время ответа и разбор структурированного вывода.
Каждый запрос обязан содержать:

```json
{ "chat_template_kwargs": { "enable_thinking": false } }
```

Это фиксируется в клиенте инференса, а не оставляется на умолчание сервера.

## Поиск

Одна коллекция Qdrant на обе ветви гибридного поиска (ADR-0003):

- плотные векторы `bge-m3`, размерность 1024, косинусная мера;
- разреженные векторы BM25 с модификатором `idf`, считаются на стороне клиента и видеопамять
  не занимают.

Единая коллекция — требование ADR-0003: фильтр по правам применяется к запросу целиком и не может
быть обойдён через одну из ветвей. Схема и индексы по полям — `configs/qdrant-collection.json`,
создаются скриптом при первом запуске.

`BM25_LANGUAGE=russian` в `.env` задаёт стемминг и стоп-слова для сервиса поиска. Без русской
конфигурации токенизации свободные описания симптомов находятся заметно хуже — при реализации
сервиса поиска этот параметр обязателен к применению.

## Сеть и доступ

Все порты публикуются на `127.0.0.1`. Арендованный узел имеет публичный адрес, а ADR-0001 требует
закрытого периметра, поэтому наружу не выставлено ничего. Доступ с рабочей машины — SSH-туннелем:

```bash
ssh -N -L 8001:127.0.0.1:8001 -L 6333:127.0.0.1:6333 -L 3000:127.0.0.1:3000 root@<адрес>
```

| Что | Адрес после туннеля |
|---|---|
| Языковая модель | `http://127.0.0.1:8001/v1` |
| Обработка изображений | `http://127.0.0.1:8002/v1` |
| Векторные представления | `http://127.0.0.1:8003/v1` |
| Qdrant | `http://127.0.0.1:6333/dashboard` |
| Langfuse | `http://127.0.0.1:3000` |
| Grafana | `http://127.0.0.1:3001` |

Скрипт дополнительно вносит в `/etc/hosts` чёрную дыру для известных адресов внешних сервисов
генеративного AI — требование ADR-0001, «Проверка соблюдения». Это защита от случайного вызова
(забытый SDK, пример из документации), **а не граница безопасности**: полноценное ограничение
исходящего трафика задаётся правилами группы безопасности на стороне облака. Отключается
переменной `ENABLE_EGRESS_GUARD=0`.

## Конфигурация и секреты

`infra/.env` создаётся скриптом из `infra/.env.example` и содержит только несекретную
конфигурацию: адреса служб, порты, имена моделей, параметры поиска (`docs/security/security.md`,
раздел 5). Секретов в нём нет.

Секреты — отдельные файлы в `infra/secrets/`, по одному на секрет. Их генерирует `bootstrap.sh`
при первом запуске; каталог получает права `700` и в git не попадает (`.gitignore`). В контейнеры
секреты передаются механизмом Docker secrets и доступны внутри как `/run/secrets/<имя>`.

| Секрет | Службы | Как передаётся |
|---|---|---|
| `vllm_api_key` | три экземпляра vLLM, `api` | vLLM — обёрткой в `VLLM_API_KEY`; `api` — файлом |
| `postgres_password` | `postgres`, `api`, `mock-erp` | `POSTGRES_PASSWORD_FILE` |
| `qdrant_api_key` | `qdrant`, `api` | Qdrant — обёрткой в `QDRANT__SERVICE__API_KEY`; `api` — файлом |
| `mock_erp_token` | `api`, `mock-erp` | `MOCK_ERP_TOKEN_FILE` |
| `langfuse_postgres_password` | `langfuse-postgres`, Langfuse | `POSTGRES_PASSWORD_FILE`; Langfuse — обёрткой |
| `langfuse_salt`, `langfuse_nextauth_secret`, `langfuse_encryption_key` | Langfuse | Обёрткой |
| `clickhouse_password` | `clickhouse`, Langfuse | `CLICKHOUSE_PASSWORD_FILE`; Langfuse — обёрткой |
| `redis_password`, `redis_conf` | `redis`, Langfuse | Redis — файлом конфигурации `redis_conf`; Langfuse — обёрткой |
| `minio_root_password` | `minio`, Langfuse | MinIO — обёрткой в `MINIO_ROOT_PASSWORD`; Langfuse — обёрткой |
| `grafana_admin_password` | `grafana` | `GF_SECURITY_ADMIN_PASSWORD__FILE` |
| `hf_token` | загрузка весов в `bootstrap.sh` | Необязательный, кладётся вручную только для закрытых весов |

Образы vLLM, Qdrant, Langfuse и MinIO не умеют читать секрет из файла. Для них точка входа заменена
обёрткой `configs/secrets-entrypoint.sh`: она переводит секреты в переменные окружения процесса
и запускает исходную команду образа. В описание контейнера и в аргументы командной строки секрет
не попадает. Собственный код (`api`, `mock-erp`) читает секреты из файлов по переменным `*_FILE`.

Повторный запуск существующие секреты **не меняет**: перевыпуск рассогласовал бы их с уже
созданными томами хранилищ. Порядок перевыпуска при компрометации — `docs/security/security.md`,
раздел 5.

**Переход с прежней схемы.** Если на узле остался `infra/.env` с секретами, первый запуск
переносит их значения в `infra/secrets/` и удаляет из `.env`, поэтому существующие тома баз
данных остаются доступны.

## Восстановление после вытеснения

Скрипт устанавливает юнит `service-desk-ai.service`, который после перезагрузки выполняет
`bootstrap.sh --boot`. Пакеты, образы и веса уже на диске, поэтому восстановление занимает минуты.

```bash
systemctl status service-desk-ai
journalctl -u service-desk-ai -f
```

Тома Docker переживают перезапуск контейнеров, но не пересоздание сервера. Отдельного плана
резервного копирования томов пока нет — появится вместе с первым реальным запуском.

## Что проверяется только на реальной машине

Места, которые невозможно проверить без сервера с GPU, помечены в исходниках комментарием
`ПРОВЕРИТЬ НА МАШИНЕ`. Найти все:

```bash
grep -rn "ПРОВЕРИТЬ НА МАШИНЕ" infra/
```

Основное: тег образа vLLM и точные имена его ключей командной строки, имя пакета драйвера NVIDIA,
необходимость перезагрузки после его установки, фактическое деление видеопамяти между тремя
моделями, имя утилиты загрузки весов Hugging Face, исходные точки входа образов, заменённые обёрткой
секретов, и чтение файлов секретов непривилегированными процессами контейнеров.

## Фиксация моделей и endpoint ERP

В `infra/.env` задаются независимые пары `LLM_MODEL_ID` / `LLM_MODEL_REVISION`,
`VISION_MODEL_ID` / `VISION_MODEL_REVISION`, `EMBED_MODEL_ID` / `EMBED_MODEL_REVISION`.
ID — репозиторий Hugging Face, REVISION — его immutable commit SHA из 40 строчных hex-символов.
Проверенные примеры SHA приведены в `.env.example`. При смене модели нужно заменить оба значения.
Названия `*_SERVED_NAME` — отдельные API aliases, ревизии они не заменяют.

Bootstrap требует все три SHA, загружает именно их (`--revision` / `snapshot_download(revision=...)`),
не пропускает проверку загрузки только из-за наличия каталога модели. При `PREFETCH_MODELS=0`
загружает vLLM, но фиксация SHA остаётся обязательной. Compose передаёт `--revision` и
`--tokenizer-revision`; backend сохраняет те же SHA в ARTIFACT_VERSION. После изменения SHA
нужно пересоздать соответствующий vLLM и API, чтобы конфигурация и работающие веса совпадали.
Команды без инференса и тесты на явных заглушках могут работать без моделей.

`ERP_BASE_URL=http://mock-erp:8100/sap/opu/odata4/sap/zai_service/0001/` направляет
SapODataAdapter на PostgreSQL mock ERP. Авторизация использует существующий файл
`MOCK_ERP_TOKEN_FILE`; секрет не помещается в URL или `.env`. `MOCK_ERP_URL` сохранён для
регрессионных проверок старого `/v1`, рабочий API использует ERP_BASE_URL.
