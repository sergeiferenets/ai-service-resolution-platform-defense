# ADR-0008. Цикл диагностического уточнения

| | |
|---|---|
| Статус | Accepted (принято) |
| Дата | 08.09.2026 |
| Поправка | 24.09.2026: решение сохранено как target/evolution direction; автоматический clarification/resume в текущем MVP не реализован |
| Контекст решения | Поведение системы при недостатке данных для выбора маршрута |
| Связанные решения | ADR-0002 (разделение ответственности), ADR-0004 (классификация правил) |

## Контекст

По ADR-0004 правило относится к требующим оценки, если необходимых признаков нет при регистрации обращения. В области MVP таких правил половина.

Отсюда следует, что однопроходный сценарий недостаточен. Получив сообщение о коде HP 49.xx, система не может выбрать маршрут: инструкция производителя предписывает выяснить, сохраняется ли ошибка после перезапуска, воспроизводится ли она при отключённых сетевом и USB-подключениях, связана ли с конкретным заданием. До получения этих сведений любой выбор будет угадыванием.

То же для ошибки сканирующего блока: официальный бюллетень производителя прямо предписывает проверить транспортный фиксатор, что для недавно перемещённого оборудования разрешает случай без выезда.

Требуется механизм, позволяющий системе сообщить о недостатке данных и получить их.

## Критерии выбора

| № | Критерий |
|---|---|
| C-1 | Гарантированная завершаемость: процесс не может длиться неопределённо |
| C-2 | Ограниченность трудозатрат на реализацию |
| C-3 | Отсутствие вопросов, ответ на которые уже известен из учётной системы |
| C-4 | Безопасность предлагаемых проверок для неподготовленного человека |

## Рассмотренные варианты

### Вариант A. Без уточнения, выбор по имеющимся данным

Отклонён. Для половины правил области MVP означает угадывание маршрута. Ошибочный выезд стоит дороже вопроса, а ошибочный отказ от выезда оставляет партнёра без обслуживания.

### Вариант B. Открытый диалог

Агент ведёт свободную переписку до достижения определённости.

Отклонён. Нарушает C-1: не гарантирует завершения, требует защиты от зацикливания, непредсказуем по числу обращений к модели. Объём реализации и тестирования не ограничен.

### Вариант C. Один раунд структурированных вопросов

Принят.

## Решение

**Один раунд уточнения, не более пяти вопросов, без продолжения диалога.**

Порядок:

1. Механизм правил определяет применимые правила. Если среди них есть требующие оценки либо остаётся несколько равноправных кандидатов, процесс переходит к уточнению.
2. Policy Agent формирует пакет вопросов. Каждый вопрос сопровождается перечнем ожидаемых ответов; свободный ответ допускается как дополнение.
3. Вопросы, ответ на которые содержится в учётной системе, не задаются: модель оборудования, срок гарантии, наличие договора, история обслуживания получаются инструментами.
4. Процесс приостанавливается, состояние сохраняется. Ожидание ответа ограничено по времени.
5. По получении ответов правила применяются повторно с расширенным набором признаков.
6. Если определённость не достигнута, обращение эскалируется человеку. Второй раунд не выполняется.

**Обоснование ограничения одним раундом.** Завершаемость обеспечивается устройством процесса, а не проверкой счётчика: второго круга не существует. Практика показывает, что диагностическое дерево производителя на первом уровне ветвления обычно разрешается тремя-пятью признаками; случаи, требующие большего, относятся к тем, где решение всё равно принимает специалист.

**Предлагаемые проверки должны быть безопасны.** Вопросы могут предполагать простые действия: перезапуск, отключение кабеля, печать внутренней тестовой страницы, осмотр транспортного фиксатора. Действия, требующие вскрытия корпуса, работы с нагретыми узлами или разборки, представителю партнёра не предлагаются ни при каких обстоятельствах. Для роли инженера перечень допустимых проверок шире.

**Изображение как источник признаков.** Для дефектов печати фотография листа переводится в диагностические признаки — направление и характер полос, повторяемость, локализация — и используется наравне с ответами на вопросы. Окончательный диагноз по изображению не ставится: модель обработки изображений поставляет признаки, решение принимается правилами и агентом.

Это расширяет применение мультимодальности за пределы распознавания идентификационной таблички и обосновывается предметно, а не желанием показать возможность.

**Уточнение относится к MVP частично.** Обязательны механизм приостановки процесса, формирование пакета вопросов и повторное применение правил. Извлечение признаков дефекта из фотографии листа отнесено к доработке после 25.09.

## Поправка 24.09.2026: отклонение текущего MVP

Решение остаётся принятым как target/evolution direction и не переписывается задним числом. В текущем baseline автоматическое формирование вопросов, переход в приостановку и resume после ответа не реализованы. Для `requires_evaluation` Policy Agent оценивает применимость одного уже выбранного правила через минимальный `PolicyCase`; `not_applicable`, `insufficient`, невалидный ответ или иная неопределённость безопасно ведут к человеку. Route при `applicable` берётся из rule catalog.

Текущее отклонение и зарезервированное, но не используемое runtime состояние `ОжиданиеУточнения` зафиксированы в [conformance](../architecture/conformance.md) и [диаграммах последовательности](../architecture/sequence-and-states.md). Реализация исходного решения требует отдельного изменения runtime и в этот MVP не входит.

## Последствия

**Положительные.** Половина правил области MVP становится разрешимой без угадывания. Появляется содержательное обоснование конечного автомата: приостановка с сохранением состояния и возобновлением по внешнему событию линейным сценарием не выражается. Поведение системы приближается к работе диспетчера. Отсутствие второго раунда гарантирует завершение.

**Отрицательные и принимаемые.** Растёт число обращений к модели и общее время обработки. Появляется состояние ожидания ответа, требующее ограничения по времени и обработки истечения. Интерфейс усложняется. Качество вопросов становится отдельным предметом проверки: бесполезный вопрос хуже отсутствия вопроса.

## Compliance & Ethics

**Безопасность предлагаемых действий.** Перечень допустимых проверок ограничен ролью обратившегося. Ошибка здесь способна причинить вред человеку, поэтому ограничение реализуется правилом, а не формулировкой запроса к модели.

**Отсутствие давления на пользователя.** Вопросы предполагают возможность ответа «не знаю» без последствий. Незнание ответа не является основанием для отказа в обслуживании и приводит к эскалации, а не к тупику.

**Прозрачность.** Пользователю сообщается, зачем задаются вопросы: для выбора между удалённым устранением и выездом. Уточнение не должно восприниматься как препятствие к получению услуги.

**Границы полномочий.** Уточнение расширяет набор признаков, но не расширяет полномочий агента: маршрут по-прежнему выбирается только из предусмотренных правилами.

**Приоритет безопасности сохраняется.** Признаки опасности прерывают процесс на любом этапе, включая этап ожидания ответов на вопросы.

## Проверка соблюдения

- Второй раунд уточнения невозможен по устройству процесса.
- Вопросы о сведениях, доступных в учётной системе, не формируются.
- Перечень предлагаемых проверок ограничен ролью обратившегося.
- Истечение времени ожидания приводит к эскалации, а не к зависанию.
- Критерии приёмки AC-6, AC-8.
