# ADR-0007. Развёртывание и устойчивость

| | |
|---|---|
| Статус | Accepted (принято) |
| Дата | 08.09.2026 |
| Контекст решения | Схема размещения MVP и поведение системы при отказе зависимостей |
| Связанные решения | ADR-0001 (локальный контур), ADR-0006 (адаптер) |

## Контекст

Система состоит из нескольких взаимодействующих сервисов, часть которых может быть недоступна: адаптер учётной системы зависит от внешней системы, сервис поиска и сервис инференса — от собственной инфраструктуры.

PRD, раздел 8, описывает три обязательных сценария деградации, но не описывает механизм, которым отказ обнаруживается. Без него каждое обращение будет последовательно упираться в таймауты: три вызова по тридцать секунд дают полторы минуты вместо мгновенного перехода в деградированный режим.

Отдельное обстоятельство: MVP размещается на прерываемом вычислительном узле, который может быть остановлен в любой момент.

## Критерии выбора

| № | Критерий |
|---|---|
| C-1 | Предсказуемое поведение при отказе любой зависимости |
| C-2 | Отсутствие длительных ожиданий при недоступности сервиса |
| C-3 | Восстановление узла без ручных действий |
| C-4 | Стоимость размещения в пределах учебного проекта |
| C-5 | Возможность показать целевую схему, не реализуя её |

## Решение по размещению

**MVP: единый узел.** Все контейнеры, включая сервис инференса, размещаются на одном арендованном узле с графическим ускорителем и разворачиваются одной командой.

Обоснование: разделение на узлы при трёх пользователях и одном экземпляре каждого сервиса не даёт ничего, кроме роста стоимости и сложности. Требование воспроизводимости при этом выполняется полностью.

**Целевая схема: разделение на четыре группы** — узел приложений, слой хранилищ, узел инференса в отдельной сетевой зоне, узел наблюдаемости. Описана в модели C4 отдельным представлением, в MVP не реализуется.

Разделение зафиксировано явно: физическое размещение MVP не является архитектурой продукта. Это не расхождение документации с реализацией, а сознательное решение, обоснованное стоимостью и сроком.

**Группировка сервисов по профилям.** Основной профиль (инференс, хранилища, приложение, мок учётной системы) и профиль наблюдаемости. При восстановлении узла первым поднимается основной; наблюдаемость стартует следом и работу не задерживает.

**Восстановление после вытеснения.** Разворачивание выполняется идемпотентным сценарием без ручных шагов. Данные, требующие сохранности между пересозданиями (веса моделей, тома хранилищ), размещаются вне контейнеров.

**Ограничение исходящего трафика.** Требование локального контура по ADR-0001 обеспечивается на двух уровнях: правилами группы безопасности на стороне площадки (действительная граница) и локальной блокировкой известных адресов внешних сервисов генеративных моделей (защита от случайного обращения из библиотеки или примера кода). Второй уровень границей безопасности не является и не должен так называться.

### Рассмотренные альтернативы размещения

| Вариант | Оценка |
|---|---|
| Оркестрация контейнеров файлом описания на одном узле | **Принят.** Одна копия каждой службы, единицы одновременных пользователей, один ускоритель |
| Кластерная оркестрация | Отклонён для MVP. При одном узле добавляет уровень управления, оператор ускорителя и описания развёртывания, не давая ни масштабирования, ни доступности. Становится оправданной при независимом масштабировании инференса и приложения либо при нескольких узлах с ускорителями |
| Бессерверное исполнение | Отклонён. Холодный старт требует загрузки моделей объёмом свыше пятнадцати гигабайт в видеопамять, что несовместимо с требованием времени отклика. Ускоритель должен быть постоянно занят, тогда как модель оплаты по вызовам предполагает обратное |

### Цели восстановления

| Данные | Допустимая потеря | Время восстановления | Способ |
|---|---|---|---|
| Состояние и аудит | 24 часа | 2 часа | Ежедневная выгрузка на отдельный том |
| Векторные представления | Не применимо | 1 час | Повторная загрузка корпуса |
| Веса моделей | Не применимо | 30 минут | Отдельный том либо повторная загрузка |
| Данные мока учётной системы | Не применимо | 15 минут | Повторное заполнение из синтетического набора |
| Конфигурация | Не применимо | Входит в развёртывание | Репозиторий |

Критично для сохранности только хранилище состояния: оно содержит аудиторский след, невосстановимый иным способом. Остальное воспроизводится из репозитория и исходных данных.

### Порядок восстановления узла

1. Создание узла и запуск сценария развёртывания.
2. Восстановление хранилища состояния из последней выгрузки.
3. Загрузка документного корпуса и построение индексов.
4. Заполнение мока учётной системы.
5. Проверка работоспособности: обращение проходит сквозной путь.

Порядок проверяется не реже одного раза за период разработки: вытеснение прерываемого узла делает это проверкой в естественных условиях, а не учением.

## Решение по устойчивости

Три механизма, в порядке важности.

### 1. Бюджеты времени

Каждый вызов внешней зависимости ограничен по времени. Без этого остальные механизмы бесполезны: зависший вызов отказом не считается.

| Зависимость | Ориентир | Поведение при исчерпании |
|---|---|---|
| Адаптер, чтение | 5 с | Один повтор, затем отказ вызова |
| Адаптер, запись | 15 с | Повтор допустим только с ключом идемпотентности |
| Сервис поиска | 5 с | Отказ вызова |
| Сервис инференса | 60 с | Отказ вызова |
| Распознавание изображения | 30 с | Переход на ручной ввод |

Значения уточняются по результатам измерений и фиксируются в плане мощностей.

### 2. Повторы

Для чтения: не более одного повтора с задержкой. Для записи: повтор допустим исключительно при наличии ключа идемпотентности (ADR-0006), иначе запрещён.

Многократные повторы не применяются: при недоступности зависимости они лишь увеличивают время до перехода в деградированный режим.

### 3. Размыкатель

Применяется к трём зависимостям, чьи отказы предусмотрены сценариями деградации.

| Зависимость | Поведение при размыкании |
|---|---|
| Адаптер учётной системы | Рекомендация формируется только по документации; отсутствие фактических данных указывается явно; создание документа заблокировано |
| Распознавание изображения | Запрашивается ручной ввод серийного номера; уровень достоверности идентификации — «со слов» |
| Сервис поиска | Гипотеза не формируется, обращение эскалируется. Ответ без источников не выдаётся |

Параметры: размыкание после пяти последовательных отказов, пробное восстановление через тридцать секунд, возврат в рабочее состояние после одного успешного вызова.

**К сервису инференса и к хранилищу состояния размыкатель не применяется.** Без первого процесс невозможен, без второго система недоступна целиком: размыкать нечего, возвращается явная ошибка.

### 4. Параллельное выполнение независимых шагов

Получение фактов из учётной системы и поиск по документации независимы и выполняются одновременно. Это даёт больше, чем кэширование, и не создаёт риска устаревания данных.

## Последствия

**Положительные.** Переход в деградированный режим занимает секунды. Поведение при каждом отказе описано и проверяемо. Узел восстанавливается без ручных действий, что превращает ограничение прерываемой машины в выполненное требование воспроизводимости. Целевая схема показана, не будучи реализованной.

**Отрицательные и принимаемые.** Единый узел является единой точкой отказа; для MVP это принято сознательно. Параметры бюджетов времени и порогов подобраны предварительно и требуют уточнения по измерениям. Размыкатель добавляет состояние, которое необходимо наблюдать: при неверных параметрах он способен размыкаться на кратковременных всплесках задержки.

## Compliance & Ethics

**Деградация не должна порождать домысливание.** Общее правило: при недостатке данных система сообщает об этом и передаёт решение человеку. Ни один сценарий деградации не предусматривает восполнения пробела предположением. Отсутствие фактических данных об оборудовании указывается в ответе явно, а не умалчивается.

**Блокировка записи при недоступности источника фактов.** При разомкнутом состоянии адаптера создание документа запрещено. Решение, принятое без проверки договора, гарантии и остатков, не должно приводить к действию в учётной системе.

**Сохранность аудита.** Профиль наблюдаемости может быть недоступен без последствий для доказательной части: аудиторский след ведётся в собственном хранилище состояния. Внешний инструмент трассировки является средством разработки, а не источником доказательств соблюдения требований.

**Прозрачность границы контура.** Локальная блокировка адресов не является средством защиты от намеренного обхода и не должна представляться таковой. Действительная граница обеспечивается сетевыми правилами площадки, что и указывается в разделе безопасности.

## Проверка соблюдения

- Принудительная остановка мока учётной системы в середине разбора приводит к переходу в деградированный режим за время, не превышающее бюджета одного вызова.
- Каждый из трёх сценариев деградации воспроизводится в тестах.
- Повторное разворачивание на пересозданном узле выполняется одной командой без ручных шагов.
- Критерии приёмки AC-6, AC-12.
