# Демонстрация на настоящих фотографиях табличек

Эталонный набор использует нарисованные таблички (`data/eval/nameplates/`). Для показа
распознавания на реальных снимках:

1. **Фотография.** Положите снимок таблички в `data/demo/photos/` (JPEG или PNG, до 5 МБ).
   Фотографии в репозиторий не коммитятся: на них могут быть сведения о владельце.
   Реальные фотографии используются только локально. Синтетический набор
   [`data/eval/nameplates`](../eval/nameplates/) остаётся воспроизводимым набором оценки.
2. **Карточка оборудования.** Внесите аппарат вручную в `data/demo/equipment_demo.csv`.
   Колонки — как в `data/reference/12_equipment.csv`:
   - серийный номер — как на табличке;
   - `customer_id` — существующий партнёр из `data/reference/11_partners.csv`;
   - `model_id` — существующая модель из `data/reference/01_models.csv`.

   Реальные серийные номера и корпоративные идентификаторы в этом CSV допустимы только
   как локальные изменения стенда: не добавляйте их в git. Отслеживаемый файл должен
   оставаться синтетическим; наличие `.gitignore` для фотографий не защищает CSV от коммита.

   Загрузчик объединяет файл со справочником. Повтор идентификатора или серийного номера —
   ошибка загрузки, а не молчаливая замена.
3. **Мок.** Пересоберите мок и перезаполните его базу:
   `docker compose --profile core --profile app up -d --build mock-erp`, затем
   `docker exec mock-erp python -m app.seed --reset`.
4. **Обращение.** Отправьте обращение с фотографией от имени представителя партнёра:
   `python data/demo/submit_photo.py data/demo/photos/<файл> --user U-019 --text "Не печатает"`.

Если номер с таблички найден в справочнике, уровень достоверности — «распознан». Если не
найден — «со слов», признак расхождения и запрос ручного ввода (PRD 5.3).
